# House Style

*Editorial rules and writing standards for OSTTRA Marketing, Product Marketing, and GTM Enablement. Brand capitalisation (OSTTRA) and the 7 unified solution families are governed exclusively by brand.md (Sections 5 & 6). This document complements brand.md; where they differ, brand.md takes precedence on brand language and corporate taxonomy, while this file governs editorial judgements and sentence construction.*

---

## 1. Voice & narrative focus

- **UK English only:** Strict British spelling across all copy. Sentence-case headings (capitalise only the initial word, proper nouns, and all-caps acronyms).
- **Audience:** Written for operational leaders, risk heads, treasurers, and business executives at banks, asset managers, hedge funds, brokers, or financial market infrastructures (FMIs).
- **Customer first:** Lead with what changes in the client's world, followed by the platform capability that delivers it. Never the other way round.
- **Clarity and brevity:** One idea per sentence. Short, scannable paragraphs.
- **Specific beats grand:** Use concrete metrics, operational workflows, regulatory deadlines, or named market processes rather than broad generalisations.
- **Accessible, not academic:** A whitepaper, roadmap, or brief is a clear argument a busy executive can absorb quickly, not an academic literature review.
- **Value focus:** Emphasise tangible operational outcomes: manual touchpoints eliminated, trade breaks resolved, settlement certainty gained, and capital optimised.

## 2. Always

- **Always UK English:** Rigorously chase out US spelling across all drafts using the canonical chase-out table below:

### The UK spelling chase-out table

| US Spelling (Prohibited) | UK Spelling (Mandatory) | Context & Application |
|---|---|---|
| `-ize` (*optimize, prioritize, centralize, categorize, specialize, penalize, authorize, realize*) | `-ise` (*optimise, prioritise, centralise, categorise, specialise, penalise, authorise, realise*) | Applies to all verbs and derived adjectives. |
| `-ization` (*optimization, standardization, centralization, harmonization, authorization, realization*) | `-isation` (*optimisation, standardisation, centralisation, harmonisation, authorisation, realisation*) | Applies to all abstract nouns. |
| `-or` (*color, behavior, favor, honor, neighbor, labor*) | `-our` (*colour, behaviour, favour, honour, neighbour, labour*) | Applies to all standard nouns. |
| `-er` (*center, theater, caliber, fiber, meter*) | `-re` (*centre, theatre, calibre, fibre, metre*) | Use `centre` (e.g. *data centre*). **Exception:** The proprietary product name is strictly *Message Center*. Retain `meter` only for measuring instruments. |
| `analyze`, `analyzing`, `analyzer` | `analyse`, `analysing`, `analyser` | Fundamental data verb across all analytics copy. |
| `program` (schedule / initiative) | `programme` | Always `programme` for projects, schedules, or events. Retain `program` only when referring to computer executable code. |
| `gray` | `grey` | UI colours, edge states, and couching notes. |
| `defense`, `offense`, `pretense` | `defence`, `offence`, `pretence` | Standard spelling rule. |
| `canceled`, `canceling` | `cancelled`, `cancelling` | Double `l` required in UK inflections. |
| `modeled`, `modeling` | `modelled`, `modelling` | Double `l` required in financial and data modelling contexts. |
| `initialed`, `initialing` | `initialled`, `initialling` | Double `l` required. |
| `traveled`, `traveling` | `travelled`, `travelling` | Double `l` required. |
| `practice` (as verb) | `practise` (verb), `practice` (noun) | Distinction between verb (*to practise*) and noun (*good practice*). |
| `license` (as noun) | `licence` (noun), `license` (verb) | Software *licence* (noun). |
| `check` (financial / mark) | `cheque` (bank payment), `tick` (selection mark) | Use `cheque` for banking; `tick` for checkbox marks. |

- **Sentence case in headings:** Strictly use sentence case for all document titles, section headers (H1, H2, H3), subheadings, slide titles, and table captions per British English standard:
  - Capitalise only the initial word, proper nouns, and all-caps acronyms (e.g. *OSTTRA*, *ISDA*, *CFTC*, *SEC*, *SA-CCR*, *FX*, *OTC*).
  - Prohibit American Title Case (capitalising each principal word).
- **Start from the client's problem:** Describe the client's operational friction in their own words before introducing our service.
- **Commercial framing:** If a feature is worth engineering effort, it is worth communicating properly. Connect every item to a concrete operational outcome or commercial benefit, never just a technical description.
- **Keep delivery gates visually distinct:** Clearly separate live, coming, and directional ambition (`[shipped]`, `[roadmap]`, `[vision]`; see `claims.md`).
- **Outline first:** Ensure clear agreement on structure and storyline before drafting full copy.
- **Guard collateral terminology strictly:** Distinguish **factsheets** (`[shipped]` live capabilities only) from **roadmaps** (forward-looking Now/Next/Later commitments). Screen all proposed drafts for category slips.

## 3. Never

- **Marketing filler & empty superlatives:** "best-in-class", "world-class", "cutting-edge", "game-changing", "revolutionary", "disruptive", "next-gen", "seamless" (unless describing a literal straight-through processing flow).
- **Spinning gaps as strengths:** If something is delayed or missing, state it plainly or leave it out.
- **Repeating last quarter:** If a piece could be last quarter's with the dates changed, it is not finished.
- **Combat or militaristic metaphors:** Never use "going to war on breaks" or "battleground". Maintain OSTTRA's institutional, authoritative tone.

---

## 4. Decks & visuals

- **Lead with a visual concept:** Diagrams, structural hierarchies, or sequence flows; never draft text-only slides. Text supports the visual anchor, not the other way around.
- **Explicit layout structures:** Provide an explicit layout model (e.g. 3-box horizontal, node graph, split flow) before drafting slide copy.
- **Standalone intro slides:** Overview slides must function as complete, self-contained executive summaries with visual capability boxes so presenters can use them without needing subsequent slides.
- **Negative space & letterbox boundaries:** Respect slide margins and canvas boundaries. Ensure copy length leaves 15–20% buffer to prevent text-clipping.
